## A. T인터뷰 (Tech) — 기술 면접

### A-1. RAG / LLM (핵심 차별 영역)

**Q1. 별빛국회 RAG 파이프라인을 어떻게 설계했나요?**

- 흐름: 문서(법안·회의록) 수집 → **청킹** → `bge-m3`(1024차원) **임베딩** → **PostgreSQL/pgvector** 저장 → 질의 시 유사도 검색 → 컨텍스트 합성 → LLM 생성
- LangChain4j로 임베딩·검색·프롬프트 합성을 표준화
- 포인트: "검색 품질이 곧 답변 품질" — 청킹 크기·중복(overlap), 메타데이터 필터(의안ID/위원회)로 정확도 관리

**Q2. 왜 멀티 LLM을 3단계 폴백으로 구성했나요?**

- **비용·지연·가용성 트레이드오프**가 핵심
- 1순위 로컬(oMLX, Mac Studio) → 비용 0·데이터 외부유출 없음 / 2순위 Ollama(qwen3:32b) → 로컬 대안 / 3순위 Groq(llama-3.3-70b) → 로컬 장애 시 **가용성 보장**
- 실제로 로컬 LLM 서버 502 장애·IP 변경 crash가 있었기에, **폴백 없이는 서비스가 죽는다**는 걸 운영으로 체득

**Q3. pgvector를 선택한 이유는? 전용 벡터DB(Pinecone 등)와 비교하면?**

- 이미 PostgreSQL을 주 DB로 쓰므로 **운영 단순화**(단일 DB, 백업·모니터링 일원화), 비용 0
- 데이터 규모(법안 수준)에서 pgvector로 충분 / 초대규모·초저지연이 필요해지면 전용 벡터DB 검토
- 트레이드오프를 "규모에 맞게" 판단했다는 점 강조

**Q4. RAG 환각(hallucination)은 어떻게 줄였나요?**

- 검색된 컨텍스트에 **근거가 없으면 "모른다"고 답하도록** 프롬프트 제약
- 출처(법안/회의록) 제시, 컨텍스트 부족 시 fallback 응답 처리(직렬 실패 지점 제거 경험 보유)

**Q5. 한국어 임베딩으로 bge-m3를 고른 이유?**

- 다국어·한국어 성능과 1024차원의 표현력, 로컬 추론 가능(MLX) → 비용·프라이버시 이점

### A-2. Backend / Spring

**Q6. Spring Boot에서 LangChain4j를 어떻게 통합했나요?**

- 서비스 계층에서 임베딩/검색/생성을 추상화, LLM 프로바이더를 **인터페이스로 분리**해 폴백 라우팅을 주입식으로 구성

**Q7. 대용량 데이터 적재 잡은 어떻게 운영했나요?**

- 국회 데이터 수집 잡을 **스케줄링 + 스로틀링**으로 운영(법안 1,213건 적재), 누적 지연(PAUSED) 해소
- 포인트: 외부 API rate limit·DB 부하를 고려한 throttle, 시간대(UTC) cap

**Q8. PostgreSQL 성능 최적화 경험은?**

- 15년간 Oracle/MSSQL 대용량 쿼리 최적화(질병관리청 방역시스템, SK SCM 대시보드 로딩 개선)
- 별빛국회에서 국회 일정 쿼리 최적화, Flyway 마이그레이션 운영

**Q9. Redis는 어디에 썼나요?** → 반복 조회·LLM/검색 결과 캐싱으로 지연·비용 절감

### A-3. 인프라 / 운영 (JD "구축·관리·운영" 직결)

**Q10. 프로덕션 장애 대응 사례를 STAR로 말해주세요.** ⭐

- **S**: 운영 중 PostgreSQL이 디스크 풀로 PANIC, crash loop 발생
- **T**: 데이터 유실 없이 신속 복구 + 재발 방지
- **A**: 원인(디스크)·로그 진단 → 안전 백업 보존 확인 후 디스크 회수 → 기동 복구 → **NAS 백업 파이프라인(Tailscale+scp, 30일 보관)**과 디스크/백업 **Email 알림 훅** 도입
- **R**: 동일 장애 재발 방지 체계 확립, 무중단 운영 지속

**Q11. 로컬 LLM 서버를 Cloudflare Tunnel로 노출한 이유와 보안은?**

- 고정 IP·포트 오픈 없이 **아웃바운드 터널**로 안전하게 연결, IP 변경에도 대응. 공개 표면 최소화

**Q12. 모니터링은 무엇을 보나요?** → Prometheus/Grafana로 자원·LLM 응답·잡 상태. 디스크/백업은 알림 훅으로 사전 경보

**Q13. CI/품질 파이프라인은?** → GitHub Actions CI + **Testcontainers** 통합 테스트, Flyway DB 마이그레이션, 개인정보(PIPA) **감사 로그** 운영

### A-4. Agentic AI (필수요건 직결)

**Q14. Claude Code 등 Agentic AI를 개발에 어떻게 활용하나요?** ⭐

- 탐색·계획·구현·**리뷰·검증**을 역할별 에이전트로 분담하는 멀티에이전트 워크플로우
- 단순 코드 생성이 아니라 **변경마다 독립 리뷰 에이전트**로 회귀·보안 결함을 사전 차단

**Q15. AI가 만든 코드의 품질은 어떻게 담보하나요?** ⭐ (예리한 질문 대비)

- 실제 사례: 파일 단위 cherry-pick 시 **이전 PR이 추가한 분기가 조용히 사라진 회귀**를, 머지 전 리뷰 에이전트가 검출 → 수정. "AI를 쓰되 **검증 책임은 사람**"이라는 원칙
- 테스트·타입체크·빌드로 최종 검증

**Q16. 조직의 AX 전환을 맡는다면 어떻게 접근하겠나요?** (주요업무 매핑)

- 개발 영역: 표준 에이전트 워크플로우·가이드 정착, 코드리뷰/테스트 자동화
- 비개발 영역: 반복 업무의 AI 보조 도입, **가이드·위키 문서화 + 교육** (JD 주요업무 2번과 일치)

## B. C인터뷰 (Career) — 인성/경력 면접

**Q1. 자기소개 / 커리어 요약**

- "15년간 삼성전자DS·세메스·질병관리청 등 미션 크리티컬 시스템을 설계·구축한 시니어 풀스택 개발자이며, 현재 RAG 플랫폼 별빛국회를 직접 만들어 운영하며 **AI 네이티브 개발로 전환을 완수**했습니다."

**Q2. SI 풀스택에서 AI로 전환한 동기는?** ⭐

- 단순 흥미가 아니라 **실제 서비스를 만들며** 전환: "기술 학습을 증명하는 가장 좋은 방법은 운영되는 제품"이라 판단 → 별빛국회 출시·운영
- AX가 개발 패러다임을 바꾸는 흐름에 **앞서 올라타고 싶었다**

**Q3. 왜 NHN, 왜 이 AX 포지션인가요?** ⭐

- 내가 개인적으로 해온 AX 전환(Agentic 개발·RAG 운영)을 **조직 규모로 확장**할 수 있는 자리
- 게임·결제·기술을 아우르는 NHN의 그룹사 AX는 **다양한 도메인에 AI를 적용**하는 폭이 매력

**Q4. 프리랜서를 오래 했는데 조직 적응은?**

- 프리랜서로도 항상 **고객 조직의 공통모듈·아키텍처를 리드**하고 협업 프로세스(GitHub/Trello)를 도입해 왔다 → 조직 기여에 익숙

**Q5. 가장 어려웠던 프로젝트와 극복 경험 (STAR)** ⭐

- 예: 삼성전자DS 대외협력포털 — 공통모듈(메뉴/권한/공통코드/통계) 아키텍처를 **전체 기반으로 설계·리드**, 외부 시스템 인터페이스 4건 통합. 복잡한 이해관계자 조율을 문서·표준화로 해결

**Q6. 협업/갈등 해결 경험**

- 시큐레이어: 레거시에 **Vue.js를 선제 도입**하며 팀 설득 + GitHub/Trello로 형상관리·이슈트래킹 체계화

**Q7. 비개발자 대상 문서·교육 경험은? (주요업무 2번)**

- 운영 노하우·설계·핸드오프 문서를 지속 축적해 재현 가능한 운영을 구축한 경험. 이를 **가이드·교육 자료로 확장**할 수 있음

**Q8. 강점과 약점**

- 강점: 15년 백엔드 기반 위에 AI/인프라/풀스택을 **혼자 끝까지 책임지는 실행력**
